Worker kodunuzu Cloudflare'in ağına dağıtmadan önce kendi yerel makinenizde oluşturabilir, çalıştırabilir ve test edebilirsiniz. Bu, Worker kodunuzu üretimde kullanılan aynı runtime olan [`workerd`](https://github.com/cloudflare/workerd) kullanarak çalıştıran bir simülatör olan [Miniflare](/workers/testing/miniflare/) aracılığıyla mümkündür.

[Varsayılan olarak](/workers/development-testing/#defaults), Worker'ınızın bağlamaları [yerel olarak simüle edilmiş kaynaklara bağlanır](/workers/development-testing/#bindings-during-local-development), ancak [uzak bağlamalar](/workers/development-testing/#remote-bindings) ile gerçek, üretim kaynağıyla etkileşim kurmak için yapılandırılabilir.

## Temel kavramlar

### Worker yürütme vs Bağlamalar

Worker'ları geliştirirken, iki farklı kavramı anlamak önemlidir:

- **Worker yürütme**: Worker kodunuzun gerçekte nerede çalıştığı (yerel makinenizde vs Cloudflare'in altyapısında).

- [**Bağlamalar**](/workers/runtime-apis/bindings/): Worker'ınızın Cloudflare kaynaklarıyla (KV namespace'leri, R2 bucket'ları, D1 veritabanları, Queue'lar, Durable Object'ler vb.) nasıl etkileşim kurduğu. Worker kodunuzda bunlara `env` nesnesi aracılığıyla erişilir (örneğin `env.MY_KV`).

## Yerel geliştirme

**Yerel geliştirme sunucusunu şunları kullanarak başlatabilirsiniz:**

1. Cloudflare Workers CLI [**Wrangler**](/workers/wrangler/), yerleşik [`wrangler dev`](/workers/wrangler/commands/#dev) komutunu kullanarak.

<PackageManagers type="exec" pkg="wrangler" args="dev" />

2. [**Vite**](https://vite.dev/), [**Cloudflare Vite plugin**](/workers/vite-plugin/) kullanarak.

<PackageManagers type="exec" pkg="vite" args="dev" />

Hem Wrangler hem de Cloudflare Vite plugin'i arka planda [Miniflare](/workers/testing/miniflare/) kullanır ve Cloudflare ekibi tarafından geliştirilir ve sürdürülür. Wrangler ile Vite arasında ne zaman seçim yapacağınız konusunda rehberlik için [Wrangler & Vite arasında seçim](/workers/development-testing/wrangler-vs-vite/) rehberimize bakın.

- [Wrangler ile başlayın](/workers/wrangler/install-and-update/)
- [Cloudflare Vite plugin ile başlayın](/workers/vite-plugin/get-started/)

### Varsayılanlar

Varsayılan olarak, `wrangler dev` / `vite dev` (Vite plugin kullanırken) çalıştırmak şu anlama gelir:

- Worker kodunuz yerel makinenizde çalışır.
- Worker'ınızın [Wrangler yapılandırmanızda](/workers/wrangler/configuration/) bağlı olduğu tüm kaynaklar yerel olarak simüle edilir.

### Yerel geliştirme sırasında bağlamalar

[Bağlamalar](/workers/runtime-apis/bindings/), Worker'ınızın çeşitli Cloudflare kaynaklarıyla (KV namespace'leri, R2 bucket'ları, D1 veritabanları, Queue'lar, Durable Object'ler vb.) etkileşim kurmasına olanak tanıyan arayüzlerdir. Worker kodunuzda bunlara `env` nesnesi aracılığıyla erişilir (örneğin `env.MY_KV`).

Yerel geliştirme sırasında, Worker kodunuz bu bağlamalarla dağıtılan ortamda olduğu gibi aynı API çağrılarını (örneğin `env.MY_KV.put()`) kullanarak etkileşim kurar. Bu yerel kaynaklar başlangıçta boştur, ancak [Yerel veri ekleme](/workers/development-testing/local-data/) belgelerinde açıklandığı gibi bunları veriyle doldurabilirsiniz.

- Varsayılan olarak, bağlamalar **yerel kaynak simülasyonlarına** bağlanır (AI modelleri her zaman uzaktan çalıştığı için [AI bağlamaları](/workers-ai/configuration/bindings/) hariç).
- Bu varsayılan davranışı geçersiz kılabilir ve [uzak bağlamalar](/workers/development-testing/#remote-bindings) ile bağlama bazında **uzak kaynağa bağlanabilirsiniz**. Bu, Worker kodunuzu yerel olarak çalıştırırken gerçek, üretim kaynaklarına bağlanmanıza olanak tanır.
- `wrangler dev` kullanırken, `--local` bayrağını sağlayarak tüm [uzak bağlamaları](/workers/development-testing/#remote-bindings) geçici olarak devre dışı bırakabilirsiniz (ve yalnızca yerel kaynaklara bağlanabilirsiniz) (yani `wrangler dev --local`)

## Uzak bağlamalar

**Uzak bağlamalar**, yerel geliştirme sırasında yerel olarak simüle edilmiş kaynak _yerine_ dağıtılan, uzak kaynağa bağlanmak için yapılandırılmış bağlamalardır. Uzak bağlamalar [**Wrangler**](/workers/wrangler/), [**Cloudflare Vite plugin**](/workers/vite-plugin/) ve `@cloudflare/vitest-pool-workers` paketi tarafından desteklenir. Bağlama tanımında `remote: true` ayarlayarak uzak bağlamaları yapılandırabilirsiniz.

### Örnek yapılandırma

<WranglerConfig>

```jsonc title="wrangler.jsonc"
{
	"name": "my-worker",
	"compatibility_date": "$today",

	"r2_buckets": [
		{
			"bucket_name": "screenshots-bucket",
			"binding": "screenshots_bucket",
			"remote": true,
		},
	],
}
```

</WranglerConfig>

Uzak bağlamalar yapılandırıldığında, Worker'ınız hala **yerel olarak yürütülür**, yalnızca bağlamalarınızın bağlandığı altta yatan kaynaklar değişir. `remote: true` ile işaretlenen tüm bağlamalar için Miniflare, işlemlerini (örneğin `env.MY_KV.put()`) dağıtılan kaynağa yönlendirecektir. `remote: true` ile açıkça yapılandırılmayan diğer tüm bağlamalar varsayılan yerel simülasyonlarını kullanmaya devam eder.

### Ortamlarla entegrasyon

Uzak Bağlamalar [Workers Ortamları](/workers/wrangler/environments) ile iyi çalışır. Üretim verilerini korumak için bir geliştirme veya staging ortamı oluşturabilir ve [Wrangler yapılandırmanızda](/workers/wrangler/configuration/) üretim için kullanacağınızdan farklı kaynaklar belirtebilirsiniz.

**Örneğin:**

<WranglerConfig>

```jsonc title="wrangler.jsonc"
{
	"name": "my-worker",
	"compatibility_date": "$today",

	"env": {
		"production": {
			"r2_buckets": [
				{
					"bucket_name": "screenshots-bucket",
					"binding": "screenshots_bucket",
				},
			],
		},
		"staging": {
			"r2_buckets": [
				{
					"bucket_name": "preview-screenshots-bucket",
					"binding": "screenshots_bucket",
					"remote": true,
				},
			],
		},
	},
}
```

</WranglerConfig>

Yukarıdaki yapılandırmayla `wrangler dev -e staging` (veya `CLOUDFLARE_ENV=staging vite dev`) çalıştırmak şu anlama gelir:

- Worker kodunuz yerel olarak çalışır
- `env.screenshots_bucket`'a yapılan tüm çağrılar üretim `screenshots-bucket` kaynağı yerine `preview-screenshots-bucket` kaynağını kullanacaktır.

### Önerilen uzak bağlamalar

Belirli bağlamaları uzak karşılıklarına bağlanmak için yapılandırmanızı öneriyoruz. Bu hizmetler genellikle Cloudflare'in ağ altyapısına dayanır veya yerel olarak tam olarak simüle edilmeyen karmaşık backend'lere sahiptir.

Aşağıdaki bağlamaların Wrangler yapılandırmanızda `remote: true` olması önerilir:

#### [Browser Rendering](/workers/wrangler/configuration/#browser-rendering):

Gerçek headless tarayıcıyla etkileşim kurmak için. Browser Rendering için şu anda yerel simülasyon yoktur.

<WranglerConfig>
```jsonc title="wrangler.jsonc"
{
	"browser": {
		"binding": "MY_BROWSER",
		"remote": true
	},
}
```
</WranglerConfig>

#### [Workers AI](/workers/wrangler/configuration/#workers-ai):

Çıkarım için Cloudflare'in ağında dağıtılan gerçek AI modellerini kullanmak için. Workers AI için şu anda yerel simülasyon yoktur.

<WranglerConfig>
```jsonc title="wrangler.jsonc"
{
	"ai": {
		"binding": "AI",
		"remote": true
	},
}
```
</WranglerConfig>

#### [Vectorize](/workers/wrangler/configuration/#vectorize-indexes):

Doğru vektör arama ve benzerlik işlemleri için üretim Vectorize indekslerinize bağlanmak için. Vectorize için şu anda yerel simülasyon yoktur.

<WranglerConfig>
```jsonc title="wrangler.jsonc"
{
	"vectorize": [
		{
			"binding": "MY_VECTORIZE_INDEX",
			"index_name": "my-prod-index",
			"remote": true
		}
	],
}
```
</WranglerConfig>

#### [mTLS](/workers/wrangler/configuration/#mtls-certificates):

Sertifika değişimi ve doğrulama sürecinin beklendiği gibi çalıştığını doğrulamak için. mTLS bağlamaları için şu anda yerel simülasyon yoktur.

<WranglerConfig>
```jsonc title="wrangler.jsonc"
{
	"mtls_certificates": [
		{
			"binding": "MY_CLIENT_CERT_FETCHER",
			"certificate_id": "<YOUR_UPLOADED_CERT_ID>",
			"remote": true
			}
	]
}

````
</WranglerConfig>

#### [Images](/workers/wrangler/configuration/#images):

Images API'nin yüksek doğruluk versiyonuna bağlanmak ve tüm dönüşümlerin beklendiği gibi çalıştığını doğrulamak için. Cloudflare Images için yerel simülasyon [yalnızca özelliklerin bir alt kümesiyle sınırlıdır](/images/transform-images/bindings/#interact-with-your-images-binding-locally).

<WranglerConfig>
```jsonc title="wrangler.jsonc"
{
	"images": {
		"binding": "IMAGES" ,
		"remote": true
	}
}
````

</WranglerConfig>

:::note
Browser Rendering, Vectorize, mTLS veya Images için `remote: true` belirtilmezse, Cloudflare **bir uyarı verecektir**. Bu, daha üretim benzeri test deneyimi için bunu etkinleştirmeyi düşünmenizi teşvik eder.

Workers AI bağlaması için `remote` `false` olarak ayarlanırsa, Cloudflare **bir hata üretecektir**. Özellik atlanırsa, Cloudflare uzak kaynağa bağlanacak ve yapılandırmaya özelliği ekleme konusunda uyarı verecektir.
:::

#### [Dispatch Namespaces](/cloudflare-for-platforms/workers-for-platforms/get-started/developing-with-wrangler/):

Workers for Platforms kullanıcıları dispatch namespace bağlama tanımlarında `remote: true` yapılandırabilir:

<WranglerConfig>
```jsonc title="wrangler.jsonc"
{
	"dispatch_namespaces": [
		{
			"binding": "DISPATCH_NAMESPACE",
			"namespace": "testing",
			"remote":true
		}
	]
}
```
</WranglerConfig>

Bu, [dinamik dispatch Worker'ınızı](/cloudflare-for-platforms/workers-for-platforms/reference/how-workers-for-platforms-works/#dynamic-dispatch-worker) yerel olarak çalıştırmanıza olanak tanırken, onu uzak dispatch namespace bağlamanıza bağlar. Bu, çekirdek dispatch mantığınızdaki değişiklikleri gerçek, dağıtılan [kullanıcı Worker'larına](/cloudflare-for-platforms/workers-for-platforms/reference/how-workers-for-platforms-works/#user-workers) karşı test etmenize olanak tanır.

### Desteklenmeyen uzak bağlamalar

Belirli bağlamalar yerel geliştirme sırasında uzak bağlantılar için desteklenmez (yani `remote: true` ile). Bunlar her zaman yerel simülasyonları veya yerel değerleri kullanacaktır.

Aşağıdaki desteklenmeyen bağlama türlerinden herhangi biri için Wrangler yapılandırmasında `remote: true` belirtilirse, Cloudflare **bir hata verecektir**. [Uzak bağlamalar için desteklenen ve desteklenmeyen tüm bağlamalara](/workers/development-testing/bindings-per-env/) bakın.

- [**Durable Objects**](/workers/wrangler/configuration/#durable-objects): Durable Objects için uzak bağlantıları etkinleştirmek gelecekte desteklenebilir, ancak şu anda her zaman yerel olarak çalışacaktır. Ancak Durable Objects'i uzak bağlamalarla birlikte kullanmak mümkündür. Aşağıdaki [Durable Objects ve Workflows ile uzak kaynakları kullanma](#using-remote-resources-with-durable-objects-and-workflows) bölümüne bakın.

- [**Workflows**](/workflows/): Workflows için uzak bağlantıları etkinleştirmek gelecekte desteklenebilir, ancak şu anda yalnızca yerel olarak çalışacaktır. Ancak Workflows'u uzak bağlamalarla birlikte kullanmak mümkündür. Aşağıdaki [Durable Objects ve Workflows ile uzak kaynakları kullanma](#using-remote-resources-with-durable-objects-and-workflows) bölümüne bakın.

- [**Environment Variables (`vars`)**](/workers/wrangler/configuration/#environment-variables): Ortam değişkenleri yerel geliştirme ve dağıtılan ortamlar arasında farklı olması amaçlanmıştır. Bunlar yerel olarak kolayca yapılandırılabilir (örneğin `.dev.vars` dosyasında veya doğrudan Wrangler yapılandırmasında).

- [**Secrets**](/workers/wrangler/configuration/#secrets): Ortam değişkenleri gibi, gizli anahtarların da güvenlik nedenleriyle yerel geliştirme ile dağıtılan ortamlar arasında farklı değerlere sahip olması beklenir. Yerel gizli anahtar yönetimi için `.dev.vars` kullanın.

- [**Static Assets**](/workers/wrangler/configuration/#assets) Statik varlıklar hız ve değişiklikler üzerinde doğrudan geri bildirim için geliştirme sırasında her zaman yerel diskinizden sunulur.

- [**Version Metadata**](/workers/runtime-apis/bindings/version-metadata/): Worker kodunuz yerel olarak çalıştığı için, belirli dağıtılan sürümle ilişkili sürüm meta verileri (commit hash, sürüm etiketleri gibi) uygulanabilir veya doğru değildir.

- [**Analytics Engine**](/analytics/analytics-engine/): Yerel geliştirme oturumları genellikle doğrudan üretim Analytics Engine'e veri katkısında bulunmaz.

- [**Hyperdrive**](/workers/wrangler/configuration/#hyperdrive): Bu aktif olarak üzerinde çalışılıyor, ancak şu anda desteklenmiyor.

- [**Rate Limiting**](/workers/runtime-apis/bindings/rate-limit/#configuration): Yerel geliştirme oturumları genellikle dağıtılan Worker'larınızın hız sınırlarını paylaşmamalı veya etkilememelidir. Hız sınırlama mantığı yerel simülasyonlara karşı test edilmelidir.

:::note
Yukarıdaki uzak kaynaklardan herhangi birine bağlanmak için kullanım durumlarınız varsa, lütfen [`workers-sdk` depomuzda](https://github.com/cloudflare/workers-sdk) [bir özellik isteği açın](https://github.com/cloudflare/workers-sdk/issues).
:::

#### Durable Objects ve Workflows ile uzak kaynakları kullanma

Durable Object ve Workflow bağlamaları şu anda uzak olamasa da, bunları yerel geliştirme sırasında kullanabilir ve uzak kaynaklarla etkileşim kurmalarını sağlayabilirsiniz.

Bunun için iki önerilen desen vardır:

- **Uzak bağlamalarla yerel Durable Objects/Workflows:**

  [Wrangler yapılandırmanızda](/workers/wrangler/configuration/) uzak bağlamaları etkinleştirdiğinizde, yerel olarak çalışan Durable Objects ve Workflows uzak kaynaklara erişebilir. Bu, yerel olarak çalışsa da yerel geliştirme sırasında uzak kaynaklarla etkileşim kurmalarına olanak tanır.

- **Servis bağlamaları aracılığıyla uzak Durable Objects/Workflows'a erişim:**

  Uzak Durable Object veya Workflow örnekleriyle etkileşim kurmak için bunları tanımlayan bir Worker dağıtın. Ardından yerel Worker'ınızda dağıtılan Worker'a işaret eden uzak [servis bağlaması](/workers/runtime-apis/bindings/service-bindings/) yapılandırın.
  Yerel Worker'ınız daha sonra uzak dağıtılan Worker ile etkileşim kurabilecek, bu da sırayla uzak Durable Objects/Workflows ile iletişim kurabilecektir. Bu yöntemi kullanarak uzak servis bağlaması aracılığıyla bir iletişim kanalı oluşturabilir, yerel geliştirme sırasında dağıtılan Worker'ı uzak bağlamalar için proxy arayüzü olarak etkili bir şekilde kullanabilirsiniz.

### Önemli Dikkat Edilecekler

- **Veri değişikliği**: Uzaktan bağlı bağlamalarda yapılan işlemler (yazma, silme, güncelleme) hedeflenen Cloudflare kaynağındaki (önizleme veya üretim) gerçek verilerinizi etkileyecektir.

- **Faturalandırma**: Bu bağlantılar aracılığıyla uzak Cloudflare hizmetleriyle etkileşimler, bu hizmetler için standart operasyonel maliyetler doğuracaktır (KV işlemleri, R2 depolama/işlemleri, AI istekleri, D1 kullanımı gibi).

- **Ağ gecikmesi**: Bu uzaktan bağlı bağlamalarda yapılan işlemler için ağ gecikmesi bekleyin, çünkü bunlar internet üzerinden iletişim içerir.

### API

Wrangler, [Miniflare](/workers/testing/miniflare/) ile Worker kodları çalıştırırken uzak bağlama bağlantılarını desteklemek için araç yazarlarına yardımcı olmak için programatik yardımcılar sağlar.

**Ana API'ler şunları içerir:**

- [`startRemoteProxySession`](#startRemoteProxySession): Uzak bağlamalarla etkileşime olanak tanıyan proxy oturumu başlatır.
- [`unstable_convertConfigBindingsToStartWorkerBindings`](#unstable_convertconfigbindingstostartworkerbindings): Bağlama tanımlarını dönüştürmek için yardımcı.
- [`experimental_maybeStartOrUpdateProxySession`](#experimental_maybestartorupdatemixedmodesession): Proxy oturumunu kolayca başlatmak veya güncellemek için kolaylık fonksiyonu.

#### `startRemoteProxySession`

Bu fonksiyon belirli bir bağlama seti için proxy oturumu başlatır. Uzak bağlama erişimi için Cloudflare hesap ID'niz ve API token'ınızla `auth` seçeneği dahil olmak üzere oturum davranışını kontrol etmek için seçenekleri kabul eder.

Şunları içeren bir nesne döndürür:

- `ready` <Type text="Promise<void>" />: Oturum hazır olduğunda çözülür.
- `dispose` <Type text="() => Promise<void>" />: Oturumu durdurur.
- `updateBindings` <Type text="(bindings: StartDevWorkerInput['bindings']) => Promise<void>" />: Oturum bağlamalarını günceller.
- `remoteProxyConnectionString` <Type text="remoteProxyConnectionString" />: Uzak bağlama erişimi için Miniflare'a geçirilecek dize.

#### `unstable_convertConfigBindingsToStartWorkerBindings`

`unstable_readConfig` yardımcısı, yapılandırma dosyasında bulunan bağlamaların tanımını içeren `Unstable_Config` nesnesini döndürür. Bu bağlama tanımları
ancak `startRemoteProxySession` ile doğrudan uyumlu değildir. Ancak bağlama bildirimlerini `unstable_readConfig` ile okumak ve ardından
bunları `startRemoteProxySession`'a geçirmek oldukça uygun olabilir, bu nedenle wrangler bunun için `unstable_convertConfigBindingsToStartWorkerBindings`'i açığa çıkarır, bu da
`Unstable_Config` nesnesindeki bağlamaları `startRemoteProxySession`'a geçirilebilecek bir yapıya dönüştüren basit bir yardımcıdır.

:::note
Bu tür dönüşüm geçicidir. Gelecekte, türler birleştirilecek böylece yapılandırma nesnesini doğrudan `startRemoteProxySession`'a geçirebileceksiniz.
:::

#### `maybeStartOrUpdateRemoteProxySession`

Bu sarmalayıcı proxy oturum yönetimini basitleştirir. Şunları alır:

- Şunları içeren bir nesne:
  - Wrangler yapılandırmasına giden yol ve potansiyel hedef ortam
  - Worker'ın adı ve kullandığı bağlamalar
- Mevcut proxy oturum detayları (hiçbiri yoksa bu parametre `null` olarak ayarlanabilir veya sağlanmayabilir).
- Uzak proxy oturumu için kullanılacak potansiyel auth verileri.

Başlatıldıysa veya güncellendiyse proxy oturum detaylarını içeren bir nesne veya proxy oturumu gerekmiyorsa `null` döndürür.

Fonksiyon:

- İlk argümana dayanarak proxy oturumu için giriş argümanlarını hazırlar.
- Kullanılacak uzak bağlama yoksa (veya önceden var olan proxy oturumu) null döndürür, proxy oturumu gerekmediğini belirtir.
- Mevcut proxy oturumunun detayları sağlanmışsa proxy oturumunu buna göre günceller.
- Aksi takdirde yeni proxy oturumu başlatır.
- Proxy oturum detaylarını döndürür (daha sonra `maybeStartOrUpdateRemoteProxySession`'ın ikinci argümanı olarak geçirilebilir).

#### Örnek

İşte uzak bağlamalarla yerel dev oturumu sağlamak için `maybeStartOrUpdateRemoteProxySession` ile Miniflare kullanmanın temel bir örneği. Bu örnek tek bir sabit kodlanmış KV bağlaması kullanır.

<TypeScriptExample>

```ts
import { Miniflare, MiniflareOptions } from "miniflare";
import { maybeStartOrUpdateRemoteProxySession } from "wrangler";

let mf: Miniflare | null;

let remoteProxySessionDetails: Awaited<
	ReturnType<typeof maybeStartOrUpdateRemoteProxySession>
> | null = null;

async function startOrUpdateDevSession() {
	remoteProxySessionDetails = await maybeStartOrUpdateRemoteProxySession(
		{
			bindings: {
				MY_KV: {
					type: "kv_namespace",
					id: "kv-id",
					remote: true,
				},
			},
		},
		remoteProxySessionDetails,
	);

	const miniflareOptions: MiniflareOptions = {
		scriptPath: "./worker.js",
		kvNamespaces: {
			MY_KV: {
				id: "kv-id",
				remoteProxyConnectionString:
					remoteProxySessionDetails?.session.remoteProxyConnectionString,
			},
		},
	};

	if (!mf) {
		mf = new Miniflare(miniflareOptions);
	} else {
		mf.setOptions(miniflareOptions);
	}
}

// ... `startOrUpdateDevSession()` çağıran araç mantığı ...

// ... dev oturumu artık gerekli olmadığında çalıştır
```

## `wrangler dev --remote` (Eski)

Miniflare destekli yerel geliştirmeden ayrı olarak, Wrangler ayrıca [`wrangler dev --remote`](/workers/wrangler/commands/#dev) aracılığıyla tamamen uzak geliştirme modu sunar. Uzak geliştirme [Vite plugin'inde **desteklenmez**](/workers/development-testing/wrangler-vs-vite/).

<PackageManagers type="exec" pkg="wrangler" args="dev --remote" />

**Uzak geliştirme** sırasında, Worker kodunuzun tamamı Cloudflare'in altyapısında geçici önizleme ortamına yüklenir ve kodunuzdaki değişiklikler kaydettiğinizde otomatik olarak yüklenir.

Uzak geliştirme kullanırken, tüm bağlamalar otomatik olarak uzak kaynaklarına bağlanır. Yerel geliştirmeden farklı olarak, bağlamaları yerel simülasyonları kullanmak için yapılandıramazsınız - bunlar her zaman Cloudflare'in ağındaki dağıtılan kaynakları kullanacaktır.

### Uzak geliştirme ne zaman kullanılır

- Çoğu geliştirme görevi için, en verimli ve üretken deneyim gerektiğinde [uzak bağlamalar](/workers/development-testing/#remote-bindings) ile birlikte yerel geliştirme olacaktır.
- Cloudflare'in ağına özgü ve yerel olarak yeterince simüle edilemeyen veya uzak bağlamalar aracılığıyla test edilemeyen özellikleri veya davranışları test etmek için `wrangler dev --remote` kullanmak isteyebilirsiniz.

### Dikkat Edilecekler

- Her değişiklik için yükleme/dağıtım adımı nedeniyle yineleme, yerel geliştirmeden önemli ölçüde daha yavaştır.

### Sınırlamalar

- `--remote` bayrağını kullanarak uzak geliştirme oturumu çalıştırdığınızda, zone başına 50 [rota](/workers/configuration/routing/routes/) sınırı uygulanır. [Workers platform limitleri](/workers/platform/limits/#number-of-routes-per-zone-when-using-wrangler-dev---remote) hakkında daha fazla bilgi edinin.
