## Arka Plan

Worker'ınıza metin dizileri veya JSON değerleri eklemek için bir bağlama türü olan ortam değişkenlerini ekleyebilirsiniz. Ortam değişkenleri, Worker'ınızın [`fetch` olay handler'ına](/workers/runtime-apis/handlers/fetch/) geçirilen [`env` parametresinde](/workers/runtime-apis/handlers/fetch/#parameters) mevcuttur.

Metin dizileri ve JSON değerleri şifrelenmemiştir ve uygulama yapılandırmasını saklamak için yararlıdır.

## Wrangler ile ortam değişkenleri ekleme

Wrangler kullanarak ortam değişkenleri eklemek için, Wrangler dosyanızda `[vars]` yapılandırması aracılığıyla metin ve JSON tanımlayın. Aşağıdaki örnekte `API_HOST` ve `API_ACCOUNT_ID` metin değerleridir ve `SERVICE_X_DATA` bir JSON değeridir.

<Render file="envvar-example" product="workers" />

Worker kodunuzda `API_HOST` ortam değişkenine nasıl erişileceği konusunda aşağıdaki örneğe bakın:

<Tabs> <TabItem label="JavaScript" icon="seti:javascript">

```js
export default {
	async fetch(request, env, ctx) {
		return new Response(`API host: ${env.API_HOST}`);
	},
};
```

</TabItem> <TabItem label="TypeScript" icon="seti:typescript">

```ts
export interface Env {
	API_HOST: string;
}

export default {
	async fetch(request, env, ctx): Promise<Response> {
		return new Response(`API host: ${env.API_HOST}`);
	},
} satisfies ExportedHandler<Env>;
```

</TabItem> </Tabs>

### Wrangler'da farklı ortamları yapılandırma

[Wrangler'daki Ortamlar](/workers/wrangler/environments) aynı Worker için farklı yapılandırmalar belirtmenize olanak tanır, her ortamda `vars` için farklı değerler dahil olmak üzere.
`vars` [miras alınamayan bir anahtar](/workers/wrangler/configuration/#non-inheritable-keys) olduğu için, ortamlar tarafından miras alınmaz ve her ortam için belirtilmelidir.

Aşağıdaki örnek, `API_HOST` için farklı değerlere sahip `staging` ve `production` olmak üzere iki ortam kurar.

<WranglerConfig>

```toml
name = "my-worker-dev"

# üst düzey ortam
[vars]
API_HOST = "api.example.com"

[env.staging.vars]
API_HOST = "staging.example.com"

[env.production.vars]
API_HOST = "production.example.com"
```

</WranglerConfig>

Belirli ortamlarda Wrangler komutlarını çalıştırmak için `--env` veya `-e` bayrağını geçirebilirsiniz. Örneğin, `npx wrangler dev --env staging` çalıştırarak Worker'ı `staging` adlı bir ortamda geliştirebilir ve `npx wrangler deploy --env staging` ile dağıtabilirsiniz.

[Wrangler'daki ortamlar](/workers/wrangler/environments) hakkında bilgi edinin.

## Dashboard ile ortam değişkenleri ekleme

Dashboard ile ortam değişkenleri eklemek için:
1. Cloudflare dashboard'da **Workers & Pages** sayfasına gidin.

   <DashButton url="/?to=/:account/workers-and-pages" />

2. **Overview**'da Worker'ınızı seçin.
3. **Settings**'i seçin.
4. **Variables and Secrets** altında **Add**'i seçin.
5. Bir **Type** seçin, **Variable name** girin ve **Value**'sunu girin. Bu değişken Worker'ınız için kullanılabilir hale gelecektir.
6. (İsteğe bağlı) Birden fazla ortam değişkeni eklemek için **Add variable**'ı seçin.
7. Değişikliklerinizi uygulamak için **Deploy**'u seçin.

:::caution[Düz metin dizileri ve gizli anahtarlar]
Ortam değişkeniniz bir [gizli anahtar](/workers/configuration/secrets/) ise **Secret** türünü seçin. Alternatif olarak, hesap düzeyindeki gizli anahtarlar için [Cloudflare Secrets Store](/secrets-store/)'u düşünün.
:::

## Ortam değişkenleri ve Node.js uyumluluğu

[`nodejs_compat`](/workers/runtime-apis/nodejs/) ve [`nodejs_compat_populate_process_env`](/workers/configuration/compatibility-flags/#nodejs_compat_populate_process_env) uyumluluk bayraklarını etkinleştirdiğinizde ve `disallow_importable_env` uyumluluk bayrağı ayarlanmadığında, ortam değişkenleri ayrıca global `process.env` aracılığıyla da kullanılabilir olacaktır. `nodejs_compat_populate_process_env` bayrağının, `nodejs_compat` 1 Nisan 2025 veya sonrasındaki bir uyumluluk tarihi ile kullanıldığında otomatik olarak etkinleştirildiğini unutmayın.

`process.env`, worker'da `process`'e ilk erişimde tembel olarak doldurulacaktır.

Metin değişken değerleri doğrudan açığa çıkarılır.

Dize değerlerine değerlendirilen JSON değişken değerleri ayrıştırılmış değer olarak açığa çıkarılır.

Dize değerlerine değerlendirilmeyen JSON değişken değerleri ham JSON dizesi olarak açığa çıkarılır.

Örneğin, üç ortam değişkeni, iki metin değeri ve bir JSON değeri olan bir Worker hayal edin:

```
[vars]
FOO =  "abc"
BAR =  "abc"
BAZ = { "a": 123 }
```

Ortam değişkenleri `wrangler.{json|jsonc|toml}` dosyası veya Cloudflare dashboard UI aracılığıyla eklenebilir.

`process.env.FOO` ve `process.env.BAR`'ın değerleri her biri JavaScript dizesi `"abc"` olacaktır.

`process.env.BAZ`'ın değeri JSON kodlamalı dize `"{ \"a\": 123 }"` olacaktır.

:::note
Ayrıca gizli anahtarların runtime içinde ortam değişkeninin bir formu olduğunu unutmayın, gizli anahtarlar da `process.env` aracılığıyla açığa çıkarılır.
