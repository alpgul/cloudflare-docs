Git deponuzu Worker'ınıza bağlarken, Worker'ınızı build etmek ve dağıtmak için gereken yapılandırmaları özelleştirebilirsiniz.

## Build ayarları

Build ayarları Worker'ınız içinde **Settings** > **Build**'e giderek bulunabilir.

Build ayarlarını güncellediğinizde ve kaydettiğinizde, güncellenmiş ayarlar _sonraki_ build'inize uygulanacaktır. Bir build'i _yeniden denediğinizde_, build yeniden denendiğinde mevcut olan build yapılandırmaları uygulanacaktır.

### Genel Bakış

| ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| **Git dalı**                                                                                                       | Cloudflare'in yeni commit'ler için dinlemesini istediğiniz dalı seçin. | **Build komutu** _(İsteğe bağlı)_                                                                                  | Projeniz build adımı gerektiriyorsa build komutu ayarlayın (örn. `npm run build`). Bu, örneğin Next.js veya Remix gibi [front-end framework](/workers/ci-cd/builds/configuration/#framework-support) kullanırken gereklidir.                                                                                                                                                                                                                                                         |
| **[Deploy komutu](/workers/ci-cd/builds/configuration/#deploy-command)**                                          | Deploy komutu, Worker'ınızı dağıtmak için kullanılan [belirli Wrangler komutunu](/workers/wrangler/commands/#deploy) ayarlamanıza olanak tanır. Workers Builds, `package json` dosyanızda ayarlanan Wrangler sürümünü kullanacaktır.                                                                                                                                                    |
| **Kök dizin** _(İsteğe bağlı)_                                                                                     | Projenizin yolunu belirtin. Alternatif olarak, [kendi API token'ınızı oluşturabilir](/workers/wrangler/migration/v1-to-v2/wrangler-legacy/authentication/#generate-tokens) veya zaten sahip olduğunuz birini seçebilirsiniz. |
| **Build değişkenleri ve sırları** _(İsteğe bağlı)_                                                                 | Yalnızca build'inize erişilebilir ortam değişkenleri ve sırlar ekleyin. Build değişkenleri runtime'da erişilebilir olmayacaktır. Şu anda Workers Builds, wrangler.toml dosyanız içindeki [Custom Builds](/workers/wrangler/custom-builds/) ayarlarını dikkate almaz.

### Deploy komutu

Deploy komutunuzu tercih ettiğiniz paket yöneticisini kullanarak çalıştırabilirsiniz.

`package.json` dosyanıza Wrangler deploy komutu script olarak eklediyseniz, bunu deploy komutunuz olarak ayarlayarak çalıştırabilirsiniz. Örneğin, `npm run deploy`.

Ayarlayabileceğiniz diğer deploy komutları örnekleri:

| Örnek Komut                          | Açıklama                                                                                                                                                                                                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npx wrangler deploy --assets ./public/` | Belirtilen dizinden statik varlıklarla birlikte Worker'ınızı dağıtın. Alternatif olarak [assets binding](/workers/static-assets/binding/)'i kullanabilirsiniz.                                                                                                                     |
| `npx wrangler deploy --env staging`      | [Wrangler ortamı](/workers/ci-cd/builds/advanced-setups/#wrangler-environments) Worker'ınız varsa, deploy komutunuzu ortam bayrağı ile ayarlamalısınız. Daha fazla ayrıntı için [Gelişmiş Kurulumlar](/workers/ci-cd/builds/advanced-setups/#wrangler-environments)'a bakın. |

### Üretim dışı dal deploy komutu

Üretim dışı dal deploy komutu yalnızca [üretim dışı dal build'leri](/workers/ci-cd/builds/build-branches/#configure-non-production-branch-builds)'ni etkinleştirdiğinizde geçerlidir.

Varsayılan olarak `npx wrangler versions upload` olur ve [önizleme URL'si](/workers/configuration/previews/) üretir. Build ve deploy komutları gibi, bunun yerine herhangi bir şeyi çalıştırmak için özelleştirilebilir.

Ayarlayabileceğiniz diğer üretim dışı dal deploy komutları örnekleri:

| Örnek Komut                              | Açıklama                                                                                                                                                                                                                                                                                           |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `yarn exec wrangler versions upload`     | Wrangler'ı çalıştırmak için kullanılan paket yöneticisini özelleştirebilirsiniz.                                                                                                                                                                                                                       |
| `npx wrangler versions upload --env staging` | [Wrangler ortamı](/workers/ci-cd/builds/advanced-setups/#wrangler-environments) Worker'ınız varsa, üretim dışı dal deploy komutunuzu ortam bayrağı ile ayarlamalısınız. Daha fazla ayrıntı için [Gelişmiş Kurulumlar](/workers/ci-cd/builds/advanced-setups/#wrangler-environments)'a bakın. |

### API token

Workers Builds'daki API token, Workers Builds'ın hesabınızın kaynaklarıyla etkileşim için verilen erişimi tanımlar. Şu anda yalnızca kullanıcı token'ları desteklenmektedir, hesap sahipli token desteği yakında gelecektir.

**Create new token**'ı seçtiğinizde, aşağıdaki izinlerle otomatik olarak yeni bir API token oluşturulacaktır:

- **Hesap:** Hesap Ayarları (okuma), Workers Scripts (düzenleme), Workers KV Storage (düzenleme), Workers R2 Storage (düzenleme)
- **Zone:** Hesaptaki tüm zone'lar için Workers Routes (düzenleme)
- **Kullanıcı:** Kullanıcı Detayları (okuma), Üyelikler (okuma)

Bu API token'ın izinlerini kullanıcı token'ları için **My Profile** > **API Tokens**'a giderek yapılandırabilirsiniz.

Tutarlı erişim izinlerini korumak için Worker'ınızın tüm yüklemeleri ve dağıtımları genelinde aynı API token'ı kullanmanız önerilir.

### Varsayılan değişkenler

Aşağıdaki sistem ortam değişkenleri varsayılan olarak enjekte edilir (ancak geçersiz kılınabilir):

| Ortam Değişkeni    | Enjekte edilen değer                  | Örnek kullanım durumu                                                                        |
| ------------------ | ------------------------------------- | --------------------------------------------------------------------------------------------- |
| `CI`               | `true`                                | CI'da çalıştırıldığında yerel olarak çalıştırıldığından farklı build davranışı değiştirme                                  |
| `WORKERS_CI`       | `1`                                    | Workers Builds'da çalıştırıldığında yerel olarak çalıştırıldığından farklı build davranışı değiştirme                      |
| `WORKERS_CI_BUILD_UUID` | `<build-uuid-of-current-build>` | Build UUID'sini özel iş akışlarına geçirme                                        |
| `WORKERS_CI_COMMIT_SHA` | `<sha1-hash-of-current-commit>` | Mevcut commit ID'sini hata raporlamaya geçirme, örneğin Sentry                       |
| `WORKERS_CI_BRANCH`     | `<branch-name-from-push-event`  | Dal temelinde build'i özelleştirme, örneğin `production`'da debug logging'i devre dışı bırakma |
