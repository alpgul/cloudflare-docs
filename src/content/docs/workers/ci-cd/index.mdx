Entegre build sistemi [Workers Builds](#workers-builds) kullanarak veya geliştirme iş akışınızı optimize etmek için [harici sağlayıcılar](#external-cicd) kullanarak Workers'larınız için sürekli entegrasyon ve sürekli dağıtım (CI/CD) kurabilirsiniz.

## Neden CI/CD kullanmalıyım?

Workers'larınızı dağıtmak için CI/CD pipeline kullanmak en iyi uygulamadır çünkü:

- Build ve dağıtım sürecini otomatikleştirir, manuel `wrangler deploy` komutlarına olan ihtiyacı ortadan kaldırır.
- Aynı kaynak kontrol yönetimi (SCM) sistemini kullanarak ekibiniz genelinde tutarlı build'ler ve dağıtımlar sağlar.
- Tekdüze bir ortamda dağıtım yaparak değişkenliği ve hataları azaltır.
- Üretim kimlik bilgilerine erişimi yönetmeyi basitleştirir.

## Hangi CI/CD'yi kullanmalıyım?

GitHub veya GitLab kullanıcıları için minimal kurulum ve yapılandırma gerektiren Cloudflare ekosistemi içinde tamamen entegre bir çözüm istiyorsanız [Workers Builds](/workers/ci-cd/builds)'ı seçin.

Aşağıdaki durumlarda [harici CI/CD sağlayıcılarını](/workers/ci-cd/external-cicd) kullanmanızı öneririz:

- GitHub veya GitLabs'ın self-hosted örneğine sahipseniz (şu anda Workers Builds'ın [Git entegrasyonunda](/workers/ci-cd/builds/git-integration/) desteklenmemektedir)
- GitHub veya GitLab olmayan bir Git sağlayıcısı kullanıyorsanız

## Workers Builds

[Workers Builds](/workers/ci-cd/builds), GitHub veya GitLab ile entegre olmanıza ve seçilen bir dalda (örn. `main`) her yeni push ile değişiklikleri otomatik olarak dağıtmanıza olanak tanıyan Cloudflare'in yerel CI/CD sistemidir.

![Workers Builds Workflow Diagram](~/assets/images/workers/platform/ci-cd/workers-builds-workflow.png)

Workers dağıtımlarınızı kolaylaştırmaya hazır mısınız? [Workers Builds](/workers/ci-cd/builds/#get-started) ile başlayın.

CI/CD pipeline'ınızı harici bir sağlayıcı ile kurmayı da seçebilirsiniz.
